# Output cadence

Removing the headless donor's timer worker also removed the precision relied on by existing C++ controller delays. For example, the Valkyrie driver performs12one-millisecond sleeps and a33ms sleep per frame. Those waits can grow substantially with Windows' default resolution. Keeping the same configured scene frequency does not prove the same physical refresh rate.

The PC component now requests1ms resolution once for its hardware lifetime, balances it after cleanup, and preserves/restores the process's timer-throttling policy. It keeps the previous repeating0.5ms worker excluded. It skips Windows builds before19041, where the request would have global scope, and skips no-detection diagnostics. Failed API calls leave default waits and generate a warning. [Microsoft timeBeginPeriod semantics](https://learn.microsoft.com/en-us/windows/win32/api/timeapi/nf-timeapi-timebeginperiod), [process timer policy](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-setprocessinformation).

A bounded native stand used the actual RAII header and the same12×1ms+33ms waits, without HID or any hardware access. Across12samples per phase the median was230.637ms at default resolution,52.1032ms during the scoped request, and230.864ms after release. This demonstrates the scheduling regression and balanced restoration. It is **not measured keyboard FPS**, a power benchmark or a guarantee of another controller's performance. The protocol's nominal45ms minimum itself prevents a promise of60FPS for that driver.

BLE operations previously polled WinRT completion every25ms. Multi-packet addressable frames paid this wait repeatedly. The native backend now uses the existing projected `IntoFuture`, an Arc-owned waker and a retained Condvar predicate; completion wakes the original owner thread immediately. Cancellation/timeout still cancel the operation and are checked between bounded wait slices. The real runtime adapter forwards that event wait instead of inheriting the fake-control polling implementation. No new asynchronous runtime, dependency or thread is introduced.

Tests cover wake-before-wait, callback arrival during waiting, a late callback after timeout, operation errors, the eight-second budget and the production adapter's callback path. A successful GATT submission is not acknowledgement of a visibly rendered frame. The negotiated MTU, controller, radio and configured device rate can still limit output; do not report configured Hz as measured display Hz.

The user reported lower keyboard/BLE smoothness and separately static RAM. RAM ownership/coexistence is a different gate: one specifically authorized FanControl restart restored RAM on the previous component, and the subsequent owned shutdown completed with exit0. Final cadence acceptance must use the newly built app/component, preserve other settings and separately verify RAM writes. Other hardware, optical acceptance, closed-editor cadence, power cost and the first new real reboot remain explicit until checked.
